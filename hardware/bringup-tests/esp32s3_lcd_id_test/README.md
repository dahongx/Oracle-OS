# LCD 原始 SPI 通信测试(不依赖显示库)

> ⚠️ **旧板引脚，在当前硬件上跑不通。** 本工程写死的是改版前的 GPIO：
> `CS=9 DC=10 SCK=11 MOSI=12 RST=13 BLK=14`。
> 当前板已整组改为 **`CS=13 DC=12 SCLK=14 MOSI=21 RST=47 BLK=11`**。
> 注意新板的 **GPIO11 是背光**,旧代码把它当 SCK 高速翻转 —— 会看到背光疯闪、屏幕全黑。
> 仅作历史参考，**不要直接烧到现在的板子上**。

引脚已根据**改版前**的原理图核实,见 `hardware/硬件自检说明.md`。

这一步的目的只是**快速确认 SPI 接线通不通**,不追求准确识别芯片型号(很多山寨屏本身
对 Read ID 命令支持就不完整)。真正的点亮效果验证请看 `esp32s3_lcd_fill_test`。

## 使用步骤

1. VSCode + PlatformIO 打开本文件夹
2. Upload(`pio run -t upload`)
3. `pio device monitor` 查看输出,同时肉眼观察屏幕背光有没有亮起

## 预期现象

- 背光(BLK)先被点亮 —— 先确认这个,如果背光都不亮,说明供电或 BLK 网络有问题,不用往下查了
- Read Display ID 返回值不是全 `00` 或全 `FF`,说明 CS/DC/SCK/MOSI/RST 这几根线电气上是通的
- 如果返回全零/全FF,按串口打印的提示逐项排查接线,或者直接跳到 `esp32s3_lcd_fill_test`
  用实际画面判断(有些屏幕就是不支持这条读命令,即使接线是对的)
