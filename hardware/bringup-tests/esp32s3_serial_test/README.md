# ESP32-S3 硬件自检 - 串口通信测试固件

只做一件事: 验证 **USB 能把固件下载进板子** + **ESP32-S3 能正常跑起来** + **能通过串口把初始化信息打印出来**。
不涉及 LCD / AS5600 / DRV2605L 等外围模块,先把最基础的一环确认清楚。

适用板子: ESP32-S3-WROOM-1-N8R2,USB 走芯片**原生 USB**(没有外置 CH340/CP2102 等桥接芯片)。

> ✅ **已实测验证通过**:用板子自己的 Type-C 口(原生 USB,设备管理器里 VID:PID 是
> `303A:1001`)烧录 `esp32-s3-devkitc-1` 这个 env,用真正的串口终端软件(串口调试助手/
> Arduino IDE 串口监视器都行)打开对应 COM 口、115200 波特率,能看到持续的心跳打印。
>
> **两个踩坑提醒**:
> 1. 查看打印**一定要用真正的终端软件**打开串口,不要用脚本硬摆弄 DTR/RTS 信号去读——
>    原生 USB-CDC 的连接握手对这个比较敏感,脚本经常触发不了"已连接",看起来像没打印,
>    其实固件一直在正常跑。
> 2. 如果外接了 CH340/CP2102 这类转串口小板(比如接在 J3 排针上)反而收不到任何东西,
>    先做个自环测试(模块自己的 TXD 接自己的 RXD,发字符看能不能收到)排除模块本身故障,
>    别急着怀疑板子接线或固件——正常测试直接用板子自己的 Type-C 口就够了,不需要额外接 CH340。

## 准备工作

1. 安装 [VSCode](https://code.visualstudio.com/) + [PlatformIO IDE 插件](https://platformio.org/install/ide?install=vscode)
2. 用 VSCode 打开 `esp32s3_serial_test` 这个文件夹(打开的是文件夹本身,不是某个文件)
3. 首次打开 PlatformIO 会自动下载 ESP32 平台工具链,等它跑完(右下角有进度条)

## 下载固件

1. 用 USB 数据线连接板子和电脑(注意:有的数据线只能充电不能传数据,如果识别不到设备先换一根线试试)
2. 电脑设备管理器 / `ls /dev/tty.*`(Mac)看看有没有出现新的 USB 串口设备
3. 点 VSCode 左下角 PlatformIO 图标栏里的 **Upload**(→ 箭头图标),或者命令行执行:
   ```bash
   pio run -t upload
   ```

### 如果自动下载失败(常见提示: `Failed to connect` / 一直重试)

说明板子上没有自动进入下载模式的电路(auto-download,靠 USB 的 RTS/DTR 控制 EN/IO0),需要手动进入下载模式:

1. 按住 **BOOT** 按键不放(如果板子上没有独立按键,就用杜邦线把 **GPIO0** 短接到 **GND**)
2. 按一下 **RESET/EN** 按键(或者把 EN 短接到 GND 再松开,相当于复位一次)
3. 松开 **BOOT**(松开 GPIO0 短接)
4. 这时候芯片就停在下载模式了,再执行 `pio run -t upload`
5. 下载完成后,芯片会自动复位并开始跑程序(或者你再手动按一次 RESET)

## 查看串口打印

烧录完成后,打开串口监视器:

```bash
pio device monitor
```

(波特率已经在 `platformio.ini` 里配好是 115200,不用额外设置)

```

========================================
Chip Model      : ESP32-S3
Chip Revision   : x
CPU Freq (MHz)  : 240

Free Heap (B)   : xxxxxx
SDK Version     : x.x.x
----------------------------------------
初始化完成! USB 下载与串口通信正常。
========================================
[     xxx ms] heartbeat #0 - ESP32-S3 running OK
[    1xxx ms] heartbeat #1 - ESP32-S3 running OK
...(每秒一条,持续打印)
```

看到上面这些内容,就说明:
- USB 下载电路(或手动 BOOT/RESET 时序)正常
- 主控芯片本身能正常起振、运行
- 原生 USB CDC 串口链路(USB Serial/JTAG)正常

## 排查提示

| 现象 | 可能原因 |
|---|---|
| 电脑完全识别不到 USB 设备 | USB 数据线是"只充电"线;USB 走线/焊接问题;芯片供电异常(先回到上一步用万用表测电压) |
| 能识别到设备,但 upload 一直连不上 | 需要手动进 BOOT 模式(见上面步骤);或者 BOOT/EN 走线有问题 |
| 烧录成功,但串口监视器啥都没有 | 确认监视器打开时机(原生 USB 断开重连会换新的串口设备号,重新插拔后端口号可能变了);检查 platformio.ini 里 `ARDUINO_USB_CDC_ON_BOOT` 是否生效 |
| 打印出来但 heartbeat 卡住不动/重启循环 | 大概率是电源不稳(纹波/瞬时电流不够),或者芯片本身/晶振有问题 |
